# Vulkan Research site

Astro static site. Pages are plain HTML; JavaScript loads only where something is interactive.

```sh
npm install
npm run dev       # http://localhost:4321, drafts visible
npm run build     # static site in dist/, deploy to any static host
npm run preview   # serve dist/ locally
```

## Writing a post

Add a file under `src/content/posts/<project>/`, named `YYYY-MM-DD-short-title.md`:

```md
---
title: "Giving Orion a Voice - How Our Robot Listens and Speaks"
date: 2026-09-16
type: article          # article | paper | release | milestone | update
project: orion         # must match a file in src/content/projects/
version: "v1"          # files the post under this version on the project page
summary: "One or two sentences for lists and link previews."
tags: [AI, Robotics]   # optional
draft: true            # optional: visible in `npm run dev`, left out of builds
---

Body in Markdown.
```

It appears automatically on the project timeline, the project page and the log.
The build fails with a clear message if a field is missing or misspelled.

### From Obsidian

Copy the note's body under the front matter above and keep Obsidian syntax as it is.
`src/lib/remark-obsidian.mjs` converts it at build time:

| In the note | On the site |
| --- | --- |
| `> [!hint] Title` callouts | a boxed aside |
| `![[episode.m4a]]` | an audio player for `public/audio/episode.m4a` |
| `![[image.png]]` | an image from `public/media/image.png` |
| `[[Other note]]`, `[[Other note\|label]]` | a link to the post with that title |
| ```` ```mermaid ```` blocks | a diagram (Mermaid loads only on pages that have one) |

Large media (podcasts, video) should not be committed: git keeps every version forever and the site host serves
the bandwidth. Host it on object storage (e.g. Cloudflare R2) and link to it instead.

### Interactive explainers

Use `.mdx` instead of `.md`, then import a React component from `src/explainers/` and give it a `client:` directive:

```mdx
import TwoLinkIK from "../../../explainers/TwoLinkIK.tsx";

<TwoLinkIK client:visible l1={120} l2={90} />
```

`client:visible` downloads React and the component only when the reader scrolls to it.
Fenced code blocks are syntax-highlighted at build time (Shiki, no client JS).

## 3D robot models

Orion V2 is built from the Fusion component STEP exports (assembly coordinates) in
`~/dev/cardinal/orionProject/orionV2Build/step/`. To refresh it after a CAD change:

```sh
CAD=~/dev/cardinal/orionProject
# 1. tessellate every STEP part (0.15 mm) into one glTF, mm Z-up -> m Y-up, parts grouped under
#    shoulder -> elbow -> wrist joint nodes; the optional last argument sets the pose in degrees
$CAD/orionV2CAD/.cad-venv/bin/python scripts/step2glb.py $CAD/orionV2Build/step /tmp/orion-v2-raw.glb shoulder=-20,elbow=65,wrist=-30
# 2. compress (meshopt): ~2.9 MB -> ~0.4 MB; -kn keeps the joint and part nodes
npx gltfpack -i /tmp/orion-v2-raw.glb -o public/models/orion-v2.glb -cc -kn
# 3. with `npm run preview` running, re-capture the poster shown while the model loads / without WebGL
node scripts/model-poster.mjs http://localhost:4321/projects/orion/ public/art/orion-v2-poster.png
```

A project uses a model through `model:` and `art:` (the poster) in its file in `src/content/projects/`.
Models render in an "ink" style (white surfaces, dark crease lines) to match the drawings; pass `look="shaded"`
to `<RobotViewer>` for the CAD colours. A viewer can also go into an MDX article:

```mdx
import RobotViewer from "../../../components/RobotViewer.astro";

<RobotViewer model="/models/orion-v2.glb" art="/art/orion-v2-poster.png" alt="Orion V2" />
```

## Hero slideshow

`src/components/Hero.astro` inlines the animated drawings from `src/assets/hero/` and plays each one for exactly
one animation cycle before crossfading to the next. It waits on `element.getAnimations()`, so there are no
hand-tuned timers: change a drawing's animation length and the slideshow follows.

The animated copies are generated by `node scripts/animate-hero.mjs` from the design bundle.

Rules for a hero drawing:
- Animations are CSS inside the SVG, scoped under `[data-playing]`, with a finite iteration count, and ideally
  start and end on the drawn pose.
- Give classes and `@keyframes` a unique prefix per drawing (e.g. `hk-` for Kestrel): inline SVGs share the page's CSS.
- `wide` slides are 1200×800 and keep the left ~550 px clear for the headline; `spot` slides are 600×450.

Visitors with "reduce motion" turned on see static drawings and switch with the dots. The Pause button is there for
everyone else (WCAG 2.2.2: anything moving for more than 5 s needs a way to pause it).

## Layout

- `src/content/` — projects and posts (the content)
- `src/content.config.ts` — the schema every content file is checked against
- `src/lib/content.ts` — queries, date formatting, timeline geometry
- `src/components/` — Hero, Timeline, ProjectSpread, RobotViewer, PostList
- `src/explainers/` — React components for articles
- `public/art/` — drawings and model posters; `public/models/` — `.glb` files
- `scripts/` — hero animation, STEP → glTF conversion, model poster capture
- `../vulkan-research-hero-illustration/` — the original Claude Design handoff, for reference
